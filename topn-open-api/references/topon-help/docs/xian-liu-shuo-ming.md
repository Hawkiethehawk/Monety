# 限流说明

# 1.开发者后台管理API

请勿使用爬虫抓取开发者后台报表数据，违者将被封号处理！

接口限流说明如下(尽量避免触发限流机制，频繁刷接口有可能被封号处理)：

|  |  |
| --- | --- |
| 限流方案 | 接口调用调优 |
| 单个开发者调用单个接口的并发请求数不超过1次 | 开发者的定时任务需使用串行的方式 |
| 单个开发者每分钟调用单个接口次数不超过20次 | 相同维度数据需要多次分页时，每次分页后间隔一小段时间再获取 |
| 单个开发者每半小时调用单个接口次数不超过200次 | 避免重复获取等 |

#

# 2. 数据报表API

为提高合作伙伴的变现效率，TopOn平台专门提供了数据报表查询的API接口，可查询综合报表、LTV&留存报表等数据，为防止频繁请求造成服务器故障，特对请求的频率进行控制，策略如下，请各位合作伙伴遵守。

- 开发者的定时任务必须使用串行的方式拉取，避免并行拉取时触发TopOn限流机制导致拉取失败
- 开发者的定时任务请避开在每单数小时的整点、40~55分这两个时间段启动
- 接口限流说明如下(尽量避免触发限流机制，频繁刷接口有可能被封号处理)：

|  |  |
| --- | --- |
| 限流方案 | 接口调用调优 |
| 单个开发者调用接口的并发请求数不超过3次 | 开发者的定时任务尽量使用串行的方式拉取 |
| 单个开发者每分钟调用单个接口次数不超过20次 | 1. 获取相同指标时，按相应group\_by维度多个app或多个广告位等一起请求 2. 相同维度数据需要多次分页时，每次分页后间隔一小段时间再获取 3. 数据量太大时，不同app或不同广告位等分散不同时间获取 |
| 单个开发者每分钟调用所有报表相关接口总数不超过40次 | 不同报表接口尽量在不同时间段获取 |
| 单个开发者每半小时调用所有报表相关接口总数不超过300次 | 1.历史数据基本不会更新，获取一次即可 2.当天伪实时数据更新有延迟，不要高频次调用获取相同数据，比如综合报表接口每两小时更新一次，间隔两个小时获取一次即可 |
