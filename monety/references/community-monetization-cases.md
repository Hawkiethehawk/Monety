# 社区个人经验与平台优化研究

> 核验日期：2026-10-15。本文整理 Reddit、知乎、V2EX 等公开社区中的个人自报案例，并用 AdMob、TopOn、Meta 官方文档交叉核对机制。社区数据不是 Monety 用户的业务观测，也不能直接替代 TopOn/AdMob 报表。

## 使用边界

来源按证据性质分层。社区个人实测不是只能“提出假设”的低权重材料；当原文条件清楚、存在前后对照或长期记录、且与目标应用相近时，可以直接影响优化方向、排查顺序和实验优先级。它仍然不能单独证明目标应用的因果关系。

- **A 级：官方文档**。用于解释 bidding、Waterfall、floor、A/B、频控、隐私和政策，不用于推断某个应用的实时收益。
- **B+ / B / B-：个人实测**。B+ 表示多个独立作者在相近条件下方向一致；B 表示单个作者有明确条件和前后对照或长期记录；B- 表示做法具体但缺少对照、分母不完整或存在利益关系。B+/B 可以直接进入经验性策略建议和实验排序，B- 主要用于补充排查线索。所有等级都不能当作行业基准。
- **C 级：平台营销宣传、厂商广告、专栏或营销内容**。只提炼可复测的方法，不采纳其收益承诺。

页面可读性和 PDF 捕获状态分开记录：`rendered` 或正文可稳定读取的 `readable` 说明页面内容较完整；`text-fallback` 说明 PDF 保留了索引正文和链接，但不保证完整 HTML、图片或评论。`text-fallback` 默认降低页面完整性信心，不自动降低个人经验的 B+/B/B- 等级；只有关键条件缺失时才降档。`indexed-excerpt`、`blocked`、`login-required` 和 `mismatch` 只作为待复核线索。具体规则见主体 Skill 的“社区经验研究与证据转化”。

所有个人案例都应先问：样本是否足够、是否有对照组、收入是毛收入还是净收入、eCPM 与展示量是否同口径、地区和广告形式是否一致。

## 交叉验证后的方法论

### 1. 先建立分层基线

按 `广告位 × GEO × OS × 广告形式 × 用户阶段 × consent 状态` 统计：

- requests、responses、match/fill、可展示、impressions、show rate；
- eCPM、总收入、ARPDAU、单用户展示次数；
- latency、崩溃、留存、卸载、invalid traffic 和 consent rate。

广告收益仍按 `impressions / 1000 × eCPM` 拆解，但决策优先看总收入、ARPDAU、留存和延迟。请求多、展示少时，不能把 eCPM 上升理解成收益改善。

### 2. Mediation 先做稳定，再做扩张

优先使用实时竞价，保留较短的 Waterfall 尾量和兜底。AdMob、Meta、Liftoff/Unity、Mintegral 等需求源应逐个接入并做增量测试；不要一次接入大量 SDK 后再凭总收入猜原因。

TopOn 配置中同时观察 bid request、bid response、bid fill eCPM、latency 和 impression gap。长瀑布、过多并行请求或过度预加载都可能降低实际展示率。

### 3. 一次只改一个主要变量

优先测试以下顺序：

1. 预加载、请求和缓存策略；
2. rewarded 的触发节点与频控；
3. 需求源和 bidding 组合；
4. GEO 分组、floor 和排序；
5. native、banner、interstitial 的组合；
6. Meta 的增量贡献。

AdMob 官方 A/B 测试建议至少积累约 10,000 次广告请求，并运行至少两周；TopOn A/B 要检查实际分流、placement 级结果和多 placement 汇总带来的 Simpson’s paradox。小样本可以生成经验性候选、排查顺序和实验优先级，但不能形成长期配置结论。

### 4. 把广告体验纳入收益函数

rewarded 应提供即时且可兑现的权益；插屏应位于自然断点；native 只有在内容流或结果页能自然呈现时才值得测试。对每个实验同时设置留存、任务完成、延迟、崩溃和投诉护栏。

### 5. 频控、隐私和供应链是上线门槛

设置 app/ad-unit 级频控，防止重复观看、异常点击和 invalid traffic。上线前完成 UMP/TCF/ATT、app-ads.txt、测试设备、广告内容审核和隐私政策；Meta 的低 fill、AdMob 的账号限制和网络审核延迟都应纳入风险记录。

## Monety 分析时的落地模板

遇到社区案例时，按以下格式写入分析：

| 字段 | 要求 |
|:---|:---|
| 案例事实 | 原文、日期、流量、地区、广告形式、实验配置和自报结果 |
| 证据等级 | 官方文档标 A；个人实测按 B+/B/B- 标记；无数据营销内容标 C；同时记录网页快照状态 |
| 可迁移假设 | 说明适用条件，不把个案参数直接复制到目标应用 |
| 需要本地验证 | 对应 TopOn/AdMob 报表字段、客户端事件和实验分组；社区经验可以决定验证优先级 |
| 成功指标 | 总收入、ARPDAU、fill/show、留存、延迟和合规状态 |
| 回退条件 | 体验护栏、收入下滑、无效流量或数据质量异常时恢复快照 |
